# TapLink Astra — Feature matrix

Feature IDs, English names and priorities follow the proposal’s `feature_requirements.json`. Implementation details describe the standalone Android source.

| ID | Feature | Priority | Implementation | Limit or condition |
| --- | --- | --- | --- | --- |
| F01 | Dashboard and cards | Must | Wallet shows the selected card’s masked ID, balance, status and three latest entries. Cards lets users create, rename, select and confirm a freeze or unfreeze. | Campus, Commute and Weekend are seeded. New cards start at zero. A freeze blocks payments and top-ups. |
| F02 | Simulated top-up | Must | Choose HK$50, HK$100, HK$200 or a custom amount. Confirmation credits the selected card and creates a timestamped receipt with the resulting balance. | Demo funds only. A positive amount can have up to two decimal places and a maximum of HK$1,000,000. |
| F03 | Merchant payment | Must | Choose one of three merchants, enter an amount and review the card before confirming. A successful debit produces a receipt. | Invalid amounts, a frozen card or insufficient funds prevent payment. |
| F04 | Transaction history | Must | Activity groups entries by Hong Kong date. Search the merchant or description, combine card, category, type and inclusive date filters, and open a stored receipt. | Every active filter applies to the same result list. |
| F05 | Spending analysis | Must | The monthly summary shows the count and total of matching payments. A custom Android View draws a segmented category chart on a Canvas. | Search and filters narrow the totals. Top-ups and reloads do not count as spending. |
| F06 | Persistent consistent data | Must | SQLite commits the card balance, ledger entries and any low-balance inbox message in one transaction. Replaying the same reviewed operation returns its receipt. | Data is local to the installation. A rejected payment leaves the ledger and balance unchanged. |
| F07 | Screen state and feedback | Must | Compose saves the route, payment draft, review key and Activity filters across rotation. The UI shows progress, inline errors, empty results and receipts. | Text fields using the draft saver restore up to 4,096 characters. Longer drafts reopen empty after recreation. |
| F08 | Automatic reload | Should | After an affordable payment, a balance strictly below the configured threshold triggers one linked reload when enabled. | The payment must be affordable before reload. A balance equal to the threshold does not trigger a credit. |
| F09 | Low-balance alerts and messages | Should | With alerts enabled, a payment ending below the threshold creates a message in Settings → Inbox. Android can also display a notification. | The comparison uses the balance after any reload. The inbox remains available when system notifications are disabled. |
| F10 | Scheduled reminders and refresh | Should | A persistent Android job rotates the featured local stop. With reminders enabled, it records a weekly review and upcoming pass or coupon expiry messages. | Delivery is deferrable. The expiry window runs from today through three days ahead. Coupons must be saved and unredeemed. |
| F11 | Nearby service discovery | Should | Explore shows six bundled stops on a map or in a list, with type filters, stop details and an external Maps action. | Distance is straight-line from a district centre or approximate foreground location. A district can be selected when permission is denied. |
| F12 | Preferences | Should | Settings saves the default card, theme, visibility, reload threshold and amount, alert and reminder switches, and shake preference. | Hiding balances masks the wallet and widget balances. Individual transaction amounts remain visible. |
| F13 | Merchant QR entry | Could | ZXing reads a merchant QR from a camera photo or chosen image and fills the editable merchant and amount fields. | Only known merchant codes and valid amounts are accepted. The user can enter details manually and must confirm the payment. |
| F14 | Receipt sharing | Could | Wallet and Activity receipts share simulated transaction details through the Android text chooser. | Shared text follows receipt visibility. The user must explicitly reveal a hidden balance to include it. |
| F15 | Transport services | Could | An active card can buy a HK$60 monthly pass and display its validity. HK$60 in transport spending, including the pass, qualifies it for a HK$12 credit recorded in claim history. | One current pass per card and one fictional subsidy claim per card per Hong Kong calendar month. |
| F16 | Offers and rewards | Could | Browse three demo offers, read their expiry dates, save favorites and redeem coupons. The wallet stores each redemption. | One redemption per offer across all cards. A coupon is valid through its displayed Hong Kong date. |
| F17 | Home-screen widget | Could | The launcher widget shows the selected card name and its visible or masked balance. Tapping it opens Wallet. | The user must add the widget in a compatible launcher. |
| F18 | Shake visibility toggle | Could | An opt-in accelerometer gesture toggles balance visibility while the Wallet dashboard is resumed. The eye button performs the same action. | The gesture requires an accelerometer and affects balance visibility only. |
